# gsm_project_allocation_profile_binding (Resource)

Manages the Project Binding, the fallback that activates Project AllocationProfile revisions for every Environment without a Binding of its own. A Binding contains one or two revision targets; two targets use their relative `weight` values for traffic distribution. Targets reference `gsm_project_allocation_profile` Profiles of the same Project.

~> **Lifecycle:** Destroying this resource deletes the Project Binding from GSM. Environments without their own Binding then fail to allocate until a new Project Binding is created. A Binding removed outside Terraform is planned for recreation.

~> **Owner identifiers:** `project` accepts a name or an ID, but Terraform compares the values as written. Use the same form in the configuration and in the import ID, and do not switch between a name and an ID later. A different form plans a replacement even for the same owner. A replacement deletes the Binding before it creates the Binding again, so in between every Environment without its own Binding fails to allocate.

## Example Usage

```terraform
resource "gsm_project_allocation_profile_binding" "default" {
  project = gsm_project.example.name
  reason  = "activate the project fallback"

  targets {
    profile  = gsm_project_allocation_profile.default.profile_name
    revision = gsm_project_allocation_profile.default.latest_revision
    weight   = 100
  }
}
```

Weights are relative, so `9/1` and `90/10` express the same distribution. Changes replace the full target list. No separate promote or rollback resource is required.

## Import

Creating a Binding fails when its owner already has one, so import the existing Binding instead. Import a Binding with `gsm_project_allocation_profile_binding/<project>`:

```shell
terraform import gsm_project_allocation_profile_binding.example gsm_project_allocation_profile_binding/my-project
```
