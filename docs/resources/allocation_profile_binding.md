# gsm_allocation_profile_binding (Resource)

Manages the active AllocationProfile Binding for a Project or Environment. A Binding contains one or two revision targets; two targets use their relative `weight` values for traffic distribution. Targets reference AllocationProfiles owned by the same Project or Environment as the Binding.

An Environment Binding overrides the Project fallback Binding. Destroying an Environment Binding deletes that override, so the Environment returns to the Project Binding. Without a Project Binding, allocation fails in every Environment that has no Binding of its own, so keep a Project fallback unless the Project should stop allocating.

~> **Project Binding lifecycle:** Destroying a Project Binding resource deletes the Binding from GSM. Environments without their own Binding then fail to allocate until a new Project Binding is created. A Binding removed outside Terraform is planned for recreation.

~> **Owner identifiers:** `project` and `environment` accept a name or an ID, but Terraform compares the values as written. Use the same form in the configuration and in the import ID, and do not switch between a name and an ID later. A different form plans a replacement even for the same owner. A replacement deletes the Binding before it creates the Binding again, so in between an Environment falls back to the Project Binding, and replacing a Project Binding makes allocation fail in every Environment without its own Binding.

## Example Usage

```terraform
resource "gsm_allocation_profile" "project" {
  project      = gsm_project.example.name
  profile_name = "default"

  default_route {
    name = "default"

    # A Project profile can reference only Project ClusterAllocationGroups.
    destinations {
      name = gsm_project_cluster_allocation_group.default.allocation_destination_name
    }
  }
}

resource "gsm_allocation_profile_binding" "project" {
  project = gsm_project.example.name
  reason  = "activate the project fallback"

  targets {
    profile  = gsm_allocation_profile.project.profile_name
    revision = gsm_allocation_profile.project.latest_revision
    weight   = 100
  }
}

resource "gsm_allocation_profile_binding" "production" {
  project     = gsm_project.example.name
  environment = gsm_environment.production.name
  reason      = "send 10 percent of allocations to the candidate revision"

  # Keep a fixed revision while the managed profile advances to a candidate.
  targets {
    profile  = gsm_allocation_profile.production.profile_name
    revision = 1
    weight   = 90
  }

  targets {
    profile  = gsm_allocation_profile.production.profile_name
    revision = gsm_allocation_profile.production.latest_revision
    weight   = 10
  }

  # Keep a Project fallback so Environments without their own Binding can allocate.
  depends_on = [gsm_allocation_profile_binding.project]
}
```

The example assumes the production Profile has advanced beyond revision `1`. Targets must reference distinct revisions. Adjust `90/10` to `10/90` to shift traffic, then remove the first target to complete the rollout. To roll back, keep only the first target with revision `1` and weight `100`; historical revisions stay immutable.

Weights are relative, so `9/1` and `90/10` express the same distribution. Changes replace the full target list. No separate promote or rollback resource is required.

## Import

Creating a Binding fails when its Project or Environment already has one, so import the existing Binding instead. Import a Project Binding with `gsm_allocation_profile_binding/<project>` or an Environment Binding with `gsm_allocation_profile_binding/<project>/<environment>`:

```shell
terraform import gsm_allocation_profile_binding.example gsm_allocation_profile_binding/my-project/production
```
